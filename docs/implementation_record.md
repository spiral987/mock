# 実装記録 — ツール整理・選択範囲・レイヤー横軸（差分）

このセッションで行った実装の流れ、途中で出た不具合とその原因、
そして「なぜ今の形に落ち着いたか」をまとめた記録。

対象は大きく 3 つ。

1. ツールパレットの整理（アイコン化）
2. 選択範囲（投げ縄選択）と投げ縄塗り、透明色
3. レイヤーの横軸（差分 = variant）の作成・分解・切り替え

---

## 1. 実装の流れ

### 1.1 ツールの整理とアイコン

`TOOLS` はラベル文字だけのボタン列だった。これを役割ごとのグループに分け、
アイコングリッドに置き換えた。

- `src/frontend/ToolIcon.tsx` を新設。24×24 の viewBox に `stroke="currentColor"` で描く
  インライン SVG。外部アイコンフォントや画像を持ち込まないので依存が増えず、
  選択中のボタンの文字色（反転色）にそのまま追従し、拡大しても滲まない。
- `TOOL_GROUPS` で「描く / 消す・塗る / 図形 / 選択・変形」に分割。
  名前・ショートカット・説明はツールチップへ移し、盤面は記号だけにした。
  アイコンだけだと初見で分からないので、グリッドの下に現在ツール名を 1 行だけ出している。

### 1.2 選択範囲と投げ縄塗り

投げ縄選択は「履歴ハイライト用の領域指定」ではなく、**本物の選択範囲**として実装した。

- `src/engine/selection.ts` — 多角形ラスタライザ（nonzero winding + 縦 4 サブサンプルの AA）、
  マスク合成（replace / add / subtract / intersect）、輪郭抽出。
- `src/engine/operations/selectionOps.ts` — `setSelection` / `clearSelection`。
- `src/engine/operations/lassoFill.ts` — 投げ縄塗り。選択と同じラスタライザを使うので、
  投げ縄選択とまったく同じ形の判定になり、縁も同じようにアンチエイリアスされる。
- `EditorState.selection` にマスクを持たせ、ブラシ・消しゴム・図形・塗りつぶし・投げ縄塗りが従う。

### 1.3 マーチングアンツ

選択範囲の境界を流れる点線で表示。絵とは別の重ね canvas（`.selection-overlay`）に描く。
点線を動かしてもレイヤー合成をやり直さずに済む。
描画ロジックは `src/frontend/marchingAnts.ts` に切り出した（見た目の要が座標と位相の詰めで
決まるため、単体で目視・数値確認できるようにした）。

### 1.4 メイン / サブ / 透明の 3 色枠

クリスタと同じ持ち方。`X` でメイン⇄サブ、`C` で透明⇄色。
透明色は色ではなく「アルファを削る」指定で、**筆の質感を保ったまま**消える。

### 1.5 D&D で差分を作る

コマンド（+ Variant）ではなく、レイヤー移動のアフォーダンスで差分を作れるようにした。
行を持ち上げて横へずらし、別の行に落とすと隣に並ぶ差分になる。
`moveAsVariant` op を追加（`src/engine/operations/variantOps.ts`）。

### 1.6 差分の分解

逆操作。スロット行の ▸ で中の差分が縦に並び、そこから 1 枚持ち上げて外へ出すと
普通のレイヤーに戻る。`moveNode` に「スロットの出し入れの後始末」を入れたので、
既存の D&D 経路（上下・フォルダ内外・余白）すべてがそのまま分解になる。

### 1.7 設計の議論

3 つの論点を整理し、方針を決めた（詳細は「3. 設計判断」）。

- 線と塗りが分離しているレイヤーの差分をどう表現するか → フォルダを差分にする。連動は保留
- 差分の入れ子を許すか → **禁止**（平らに混ぜる）
- 切り替えのインタラクション → サムネイル + 直接操作へ

### 1.8 長押しで持ち上げる

移動と差分スライドが同じ「行を掴む」操作で衝突していたため、**向きではなく時間**で分けた。

| 操作 | 結果 |
|---|---|
| 短く押して離す | クリック（選択・開閉） |
| 押してすぐ横へ | 差分の切り替え |
| 押したまま待つ（`LAYER_LIFT_MS`） | 持ち上がる → 移動 |
| ⠿ グリップを掴む | 待たずに持ち上がる |

### 1.9 カルーセル

スライドを「見えない数え上げ」から直接操作に変えた。行の上に重なるカルーセル
（`position: absolute` なのでレイアウトは動かない）が出て、サムネイルが指について動く。
サムネイル 1 枚の間隔（`VARIANT_PITCH_PX`）とスライドの 1 段を同じ値にしてあるので、
指の移動量とサムネイルの移動量が 1:1 になり、「どこまで動かせば隣か」が目で分かる。

## 2. 発生した不具合と原因

### 2.1 マーチングアンツが「うっすい鉛筆」で動かなかった

**症状**: 選択確定後、静止した薄い灰色の線になる。

**原因は 2 つ重なっていた。**

1. **黒の実線の上に白の破線を重ねていた。**
   白い紙の上では白い破線が見えず、残るのは連続した 1 本の線だけ。
   破線が流れても見た目が変わらないので完全に静止して見えていた。
2. **輪郭が画素の境界（整数座標）を通るのに幅 1px で線を引いていた。**
   線が上下 2 行に 50% ずつ乗って灰色の薄い線になる。

**対処**: 黒と白の**両方を破線にして半周期ずらす**（線上のどの点も必ず黒か白になる）。
半画素ずらして画素の中心に載せる。拡大時に線幅が 1 キャンバス画素を割らないよう下限を付ける。
さらに破線の切れ目も画素境界に合わせて、継ぎ目の 1px グレーを消した。

**実測での確認**（ヘッドレス Chrome で画素を読み出し）:

```
上辺 y=16 をまたぐ縦スライス:
  y=15  rgba(0,0,0,0)          ← 透明
  y=16  rgba(255,255,255,255)  ← 1行だけ、完全不透明
  y=17  rgba(0,0,0,0)          ← 透明

上辺に沿った並び (B=黒 W=白):
  修正前: ?BBB?WWW?BBB?WWW   ← 継ぎ目が 1px 灰色に滲む（＋下に黒の実線）
  修正後: BBBBWWWWBBBBWWWW   ← 黒白 4px ずつ、全部不透明
```

### 2.2 variantIndex を番号で寄せていた

**症状**: 差分をスロットの外へ出すと、出ていた差分が別のものに入れ替わる。
`[A|*B|C]` から A を抜くと B が出たままであるべきなのに C になっていた。

**原因**: 取り出し後の `variantIndex` を「番号」で計算していた。
`removeVariant` の規則を写し間違えており、`cur >= removedIndex` で一括りにしていたため、
取り出した位置より右を見ていたケースが 1 つずれた。

**対処**: 番号ではなく **id で指し直す**。取り出す前に「何が出ていたか」の id を控え、
取り出した後にその id の位置へ寄せる。出ていた差分そのものを外へ出した場合だけ
「抜けた位置」へフォールバックする。前後に差分が増減しても意図が保たれる。

### 2.3 スライド開始時の移動量が捨てられていた

**症状**: 速く弾いて離すと 1 段も動かないことがある。

**原因**: 最初の `pointermove` はスライドを「開始」するだけで、その移動量を反映していなかった。
ゆっくり動かせば次の move で追いつくので気づきにくい。

**対処**: 反映処理を `updateSwipe()` に切り出し、開始した move からも呼ぶ。

### 2.4 setPointerCapture の例外で描画が黙って消える（既存の弱点）

**症状**: 検証中、合成ポインタイベントで描画だけが一切記録されなかった。

**原因**: キャンバスの `onPointerDown` が `c.setPointerCapture?.(id)` を素で呼んでいた。
`?.` はメソッドが無い場合を守るだけで、**例外は素通しする**。
`setPointerCapture` は「その pointerId がもう有効でない」ときに例外を投げる仕様なので、
投げられると **`onPointerDown` 全体が中断し、ストロークが何も言わずに失われる**。

レイヤー行側は try/catch してあったのに、キャンバス側だけ素通しだった。

**対処**: `capturePointer()` に集約し、例外を飲んで処理を続ける。
これは今回の変更で入れたものではなく元からあった弱点だが、検証手法のおかげで表面化した。

### 2.5 持ち上げ前に行の外で離すと、後から勝手に持ち上がる

**原因**: 持ち上がる前は pointer を捕捉していないので、`pointerup` が行に届かないことがある。
保留状態とタイマーが残り、離した後にタイマーが発火する。

**対処**: `window` で `pointerup` / `pointercancel` を拾って後始末する。
長押し中にコンテキストメニューが割り込むのも抑止した。

### 2.6 レイヤー行のレイアウト崩れ

**症状**: レイヤー名が「線…」まで潰れ、操作ボタンがパネルの外へはみ出していた。

**原因**: 300px 弱の行に、開閉トグル・サムネイル・名前・差分ナビ・各種ボタンを詰め込みすぎ。

**対処**: 押せないボタンを置かない方針で削った。

- 差分行から 👁（控えの差分は絵に載らない）と ⤓（差分どうしは統合できない）を削除
- スロット行からも ⤓ を削除（`canMergeDown` が常に false）
- 「表示中」バッジを文字から小さな緑の点へ
- 行の gap を 6px → 4px、レイヤーパネル幅を 270px → 300px
- サムネイル帯は行の中ではなく行の下に独立させた（後にカルーセルへ置き換え）

### 2.7 テスト側の誤り（参考）

製品コードではなくテストが悪かったもの。切り分けの記録として残す。

- 初期レイヤーの id を `background` と書いていた（正しくは `layer-base`）
- 畳んだスロットの行数を 3 と期待していた（正しくは 2）
- キーイベントを document と window の両方に投げて 2 段進んでいた

## 3. 設計判断とその理由

### 3.1 選択マスクは op に焼かず、path だけを持つ

`setSelection` op が持つのは多角形の点列だけで、マスクは apply のたびに焼き直す。

- マスク画素を op に持たせると巨大になり、replay も重くなる
- path だけなら log が軽く、**`state === replay(log)` が選択範囲まで含めて成立する**

### 3.2 選択が無いときは「元の関数をそのまま返す」

`maskStamp()` は選択が null のとき、包まずに元の `StampFn` を返す。
これにより**選択を使わない限り従来とビット同一**の結果になる。
塗りつぶしも `opacity * (255/255)` に落ちるので浮動小数の誤差も入らない。

### 3.3 透明色は「軸 B の差し替え」で実現

筆の質感は 2 つの軸でできている。

- 軸 A（`resolveProfile`）: dab をどこに・どんな形で置くか
- 軸 B（`createBrushStamp`）: 各画素にどう書き込むか

透明色は軸 B だけを `createEraseStamp`（色を置く代わりにアルファを削る）に差し替える。
軸 A はそのままなので、**Gペンなら Gペンの入り抜きで、鉛筆なら紙目を残したまま**消える。
`eraser` op の `brushType` / `brush` は省略可にしたので、
省略した op は従来の消しゴムとビット同一のまま replay できる。

### 3.4 差分の入れ子を禁止する

`[[A|B]|C]` は合成結果が平らな `[A|B|C]` と**完全に一致する**。
増えるのは「グループ内でどれを選んでいたかの記憶」だけで、表現力は増えない。
一方コストは、1 次元のレイヤー一覧に階層を描く必要が生まれて読みにくくなること。

そこで **「縦軸（フォルダ）と横軸（差分）は交互にしか積めない」** を不変条件にした。

| 入れ子 | 可否 | 理由 |
|---|---|---|
| 差分の中にフォルダ | 許す | 「この案は複数枚でできている」＝線と塗りが分離した差分の答え |
| フォルダの中に差分 | 許す | 「このグループのここだけが変わる」 |
| 差分の中に差分 | **禁止** | 表現力が増えないのにコストだけ増える |

スロットへスロットを入れる操作は、入れ子にせず**中身を平らに混ぜる**。
`moveNode` / `moveAsVariant` / `addVariant` の 3 経路すべてで保証している
（合成側の `resolveSlot` は入れ子でも壊れないので、守っているのは可読性）。

### 3.5 レイヤーコンプ方式（プリセット）を採らなかった

「線と塗りが分離しているレイヤーの差分」に対して、Layer Comps のような
名前付きプリセットは採らなかった。

**理由**: プリセットは「ノード id のリスト」という**別表**であり、
統合・削除・移動のたびに整合を取り直す必要が生まれる。
`state === replay(log)` の外側に整合性の責任ができてしまう。
このコードベースはクリッピングも `Layer.clipped` という**ノード自身が持つ値**で表現しており、
レジストリを一切持っていない。そこに別表を 1 つ足すと、
以後すべての構造 op がその表を気にする羽目になる。

**採った方針**: 大半のケースは構造だけで解ける。

- 塗りだけ変わる（線は共通） → 塗りのスロットだけ横軸にする
- 線と塗りがセットで変わり z 順で隣接 → 2 枚をフォルダに包んで、そのフォルダを差分にする

z 順で離れた場所を連動させたい場合だけ仕組みが要るが、その時も別表ではなく
`LayerGroup` に `syncKey` を持たせる案を出した（ノード側に持たせれば移動しても付いてくるし、
消えるのはそのスロットの key だけで宙ぶらりんの参照が発生しない）。
ただし**実際に手を焼くまでは作らない**方針で保留とした。

### 3.6 移動とスライドを「時間」で分ける

同じ行を掴む 2 つの操作を**向き**で分けると、斜めのドラッグが常に曖昧になる。
時間で分ければ排他になる。

- 押してすぐ横 → スライド
- 押したまま待つ → 持ち上がって移動

持ち上げは構造を変える操作なので、少し溜めがある方が誤操作も減る。
マウスで素早く並べ替えたい場合のために、⠿ グリップからは待たずに持ち上がる逃げ道を用意した。
（これで ⠿ に実際の役割ができた。従来は行のどこでも掴めるので飾りだった。）

### 3.7 差分化の判定を「行の縁」ではなく「横移動量」にする

最初は落とし先の行の左右 30px を判定領域にしていたが、
掴む ⠿ グリップが**行の左端にある**ため、そこを掴んで縦にドラッグすると
通り過ぎる行すべてで「左」判定に入ってしまう。

掴んだ位置からの横移動量（`VARIANT_DROP_DX`）で見るようにした。
「横に持っていく」という手の動きそのものを見るので、行のどこを掴んでも意図どおりに分かれる。

### 3.8 カルーセルの向き

最終的に**内容が指について動く**（写真カルーセルと同じ）方式にした。
掴んでいるのは差分の帯そのもので、中央の枠は動かない。
帯を左へ引けば帯が左へ流れ、右隣の差分が枠に入る。

途中で一度「枠の方を動かす」方式（帯が指と逆に流れる）に変えたが、
意図と違ったため戻している。

`,` / `.` キーは「前 / 次」を指すもので帯を掴んでいるわけではないため、
指の向きで見るとスワイプとキーは逆になる。これはカルーセルとしては正しい形。

## 4. 検証方法

ブラウザ拡張が使えなかったため、検証手段を段階的に組み立てた。
これが結果的に、上記のいくつかの不具合を見つける決め手になった。

### 4.1 エンジンの自己テスト（DOM なし）

esbuild で TS を CJS にバンドルして node で実行。
純 TS のエンジン部分（ラスタライザ・マスク合成・op の apply・replay 一致）を
DOM 抜きで叩けるので速い。

主な確認項目:

- 多角形の面積が理論値に近いか、斜め辺に中間被覆（AA）が出るか
- 選択範囲がブラシ・消しゴム・塗りつぶし・投げ縄塗りを正しく制限するか
- 透明色が「その筆の質感のまま」消すか（Gペンは細く、鉛筆は紙目の抜けを残す）
- 消しゴム op が `brushType` 省略時に**従来とビット同一**か
- 差分の作成・分解・並べ替えで木の形と `variantIndex` が期待どおりか
- 木全体を走査して**差分の中に差分が居ない**か
- すべてのケースで `state === replay(log)`

木の形は `[A|*B] G{X Y}` のような文字列に落として比較すると、失敗時に差分が読みやすい。

### 4.2 ヘッドレス Chrome のスクリーンショットと画素読み出し

CSS とレンダリングは目で見ないと分からない。
`chrome --headless --screenshot` で撮り、必要なら `--dump-dom` に
`getImageData` の結果を載せて数値で確認した。

これで見つけたもの: マーチングアンツの半画素滲み、レイヤー行のはみ出し、
ハーネス側の `.float-window` が `position: fixed` で全ペインが重なる問題。

### 4.3 iframe + 合成 PointerEvent による操作テスト

ジェスチャの状態機械は読んでも確かめられない。
実アプリを iframe に読み込み、`PointerEvent` を合成して投げ、
DOM（ゴーストの表示、`lifted` クラス、n/m の表示、`translateX` の値）を読み返す。

これで見つけたもの: スライド開始時の移動量が捨てられる問題、
`setPointerCapture` の例外で描画が消える問題。

## 5. 保留にしたもの

- **離れたスロットの連動（`syncKey`）** — フォルダを差分にする運用で回してみて、
  実際に手を焼く場面が出てから着手する（3.5 参照）
- **明度・色相・変形を選択範囲でクリップする** — `brightness` / `hue` は
  `Uint8ClampedArray` のクランプ前提で書かれており、部分被覆の合成を足すと丸めが変わる。
  変形は「選択部分を切り出して動かす」という別機能になる
- **拡大時のマーチングアンツの線幅** — 現状は 1 キャンバス画素固定なので拡大すると太く見える。
  画面上で常に細く見せるにはオーバーレイの解像度を表示倍率に合わせる必要があり、
  大きいキャンバスではメモリを食うため見送った
